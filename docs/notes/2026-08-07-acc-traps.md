# Traps that cost real debugging time building the ConPTY continuity mechanism

## What breaks if this is deleted

The next person (human or agent) touching `watcher/clearbot.ps1`, `winfind.ps1`, or `guards-gui.ps1`'s WinForms layout re-learns these the hard way, at real time cost — each already cost a debugging session once.

## Body

Condensed from `notes/ACC-HANDOFF.md` (deleted; its architecture description duplicated `AGENTS.md`, which stays canonical for current behavior — only this non-derivable, hard-won knowledge is preserved here).

- **Gate on what the mechanism consumes, not on what the diagnostic collects.** Auto-clear was silently dead for about a day: `winfind.ps1` returned `ok:false` whenever `EnumWindows` found no visible window, and both `captureWindow()` and `requestClear()` gated on `hwnd` — but keystroke injection is `WriteConsoleInput` addressed by PID and never touches the hwnd. The right answer was being thrown away for want of a handle nothing used.
- **A test that runs a copy is not a test.** An old `test-budget.mjs` sat in an install payload folder and ran the pre-install copy of `budget.mjs` there — every "N passed" graded a file no live session had loaded in days. Sandboxed tests now run the real `hooks/budget.mjs` with `ACC_ROOT` pointed at a throwaway tree (never the live `runner/state`, since resetting it would delete the `.window` files running sessions depend on).
- **PowerShell 5.1 prepends a UTF-8 BOM when piping JSON to a hook.** `JSON.parse` fails, `readStdin()` returns `{}`, and the hook silently emits nothing — indistinguishable from a broken hook. Use the Bash tool for hook smoke tests instead of PowerShell piping. Same BOM family as the config-loading trap `kernel/policy.mjs`'s `stripBom` now handles explicitly.
- **WinForms applies docking in reverse z-order.** A `Fill` control must be at index 0 (`BringToFront`) or it lays out before a `Top` header and the header's pixels hide behind it — group titles simply vanish. Do not `BringToFront()` the header afterward to "fix" it.
- **Call `SetProcessDPIAware()` before `GetWindowRect`,** or a screenshot captures a zoomed crop of the corner instead of the real window.
- **A running clearbot does not pick up edits to `clearbot.ps1` — it must be restarted,** and the process count checked afterward: a stop+start that doesn't fully stop the old one leaves two watchers running, which doubles every kick and every auto-approval.
- **`-SmokeTest` cannot see layout.** Screenshot the window on every GUI change (`watcher/screenshot-gui.ps1 [-Advanced]`); `-Advanced` finds a checkbox by its caption and sends `BM_CLICK` rather than clicking a coordinate, which drifts with every layout edit.
